Cluster groups

Several independent Kafkas in one application

kafka-dr:
  cluster-groups:
    core:
      clusters: { a: …, b: … }
    analytics:
      clusters: { a: …, b: … }
  consumers:
    orders-bridge:
      cluster-group: core
      depends-on: analytics

Each group lives on its own

Election, failover, failback-after, health check and environment — separately for core and analytics

Producers by name

producer.to("order-analytics").send(…).orThrow() — the name hides which Kafka holds the topic

The old form still works

kafka-dr.clusters is the group default, with the same binder names and keys as before

8

A group is one logical Kafka with its own primary and standby clusters. An application can have several, and each fails over independently: analytics going down does not touch core. A physical cluster belongs to exactly one group, checked at startup. Producers are addressed by logical name, so moving a topic to another group is a configuration change only. Existing configurations without groups keep working unchanged.
