Группы кластеров

Несколько независимых Kafka в одном приложении

kafka-dr:
  cluster-groups:
    core:
      clusters: { a: …, b: … }
    analytics:
      clusters: { a: …, b: … }
  consumers:
    orders-bridge:
      cluster-group: core
      depends-on: analytics

Своя жизнь у каждой группы

Выборы, failover, failback-after, health-check и окружение — отдельно для core и analytics

Продюсер по имени

producer.to("order-analytics").send(…).orThrow() — имя скрывает, в какой Kafka топик

Старый формат работает

kafka-dr.clusters — это группа default с прежними именами binder'ов и ключей

Kafka DR Starter

8

Группа — это одна логическая Kafka со своими основным и резервными кластерами. В одном приложении их может быть несколько, и каждая переключается независимо: падение analytics не трогает core. Один физический кластер входит только в одну группу — это проверяется на старте. Продюсер адресуется по логическому имени, поэтому перенос топика в другую группу — только изменение конфигурации. Существующие конфигурации без групп продолжают работать без изменений.
